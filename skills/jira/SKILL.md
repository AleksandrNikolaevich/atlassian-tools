# Jira: локальная копия и правка описаний

Релизы и задачи Jira выгружаются в markdown командой `jira-sync`, а описание задачи правится в разметке
Jira командой `jira-edit`. Читайте задачи по копии, описание меняйте через `jira-edit`.

## Настройки и пути

Настройки лежат в `.env` в корне проекта. **Сам `.env` не читайте и не выводите**: в нём пароли.

| Что | Где |
|---|---|
| Копия Jira | `_jira/` (настройка `JIRA_DIR`) |
| Описания в работе | `_jira-edit/` (настройка `JIRA_EDIT_DIR`) |

## Сеть: кто запускает команды

Jira обычно доступна только из сети заказчика (VPN). `jira-sync check`, `jira-sync pull` и
`jira-edit fetch`, `push` **попросите выполнить пользователя** в его терминале. Сами запускайте их,
только если пользователь прямо попросил и доступ есть. `jira-edit diff`, `check`, `status` работают без
сети — их запускайте сами.

**`jira-edit push` никогда не запускайте сами**, даже по просьбе: запись в Jira делает человек после
подтверждения в терминале.

## Как читать копию

- `_jira/README.md` — список релизов, начинайте отсюда.
- `_jira/releases/<релиз>.md` — задачи релиза таблицей, подзадачи под родителем.
- `_jira/issues/<KEY>/<KEY>.md` — задача: поля, описание, подзадачи, связи, вложения, комментарии.
- `_jira/issues/<KEY>/attachments/` — вложения; картинки открывайте, когда из текста неясно, что на них.
- Нет файла задачи — попросите пользователя выполнить `jira-sync pull <KEY>`. Не додумывайте задачу по
  ключу.
- Копия — снимок на момент выгрузки (дата в `_jira/README.md`). Если вопрос про актуальный статус,
  предложите обновить копию.

## Правка описания задачи

1. Пользователь выполняет `jira-edit fetch <KEY>` — описание появится в `_jira-edit/<KEY>.txt`
   (его правите), рядом `<KEY>.orig.txt` и `<KEY>.json` (не трогайте).
2. Правьте файл в **разметке Jira (wiki markup), не в markdown**: `h2.`, `*жирный*`, `_курсив_`,
   `-зачёркнутый-`, `* пункт`, `# пункт`, `||заголовок||`, `|ячейка|`, `[текст|ссылка]`, `{code}…{code}`,
   `{noformat}…{noformat}`, `!картинка.png!`, `[^вложение.pdf]`.
3. Правка точечная: не переформатируйте текст и не трогайте разметку вне места правки. Новую строку
   таблицы или пункт делайте по образцу соседних.
4. Новая картинка или вложение — сам файл нужно приложить к задаче в Jira вручную; скажите пользователю,
   какой.
5. Запустите `jira-edit diff <KEY>` и `jira-edit check <KEY>`, исправьте ошибки, покажите пользователю
   разницу и предупреждения.
6. Пользователь выполняет `jira-edit push <KEY>`, затем `jira-sync pull <KEY>`. Если описание успели
   изменить в Jira после `fetch`, `push` откажет: нужно `jira-edit fetch <KEY> --force` и повторить правку.

Не выдумывайте факты: чего нет в исходных материалах — не пишите в описание, а перечислите вопросы.

## Ошибки

| Сообщение | Что делать |
|---|---|
| «не задан адрес Jira», «не задан доступ к Jira», «не задан проект Jira» | Пользователь дописывает `.env` по `.env.example` пакета |
| «Jira ответила 401», «вход … не удался» | Неверный доступ, капча или SSO — войти в браузере или задать `JIRA_TOKEN` / `JIRA_COOKIE` |
| «Jira недоступна» | Нет сети до Jira — включить VPN |
| `command not found: jira-sync` | Пакет не установлен: `pipx install git+<адрес репозитория atlassian-tools>` |
