# Confluence: локальная копия и правка страниц

Вики проекта зеркалится в markdown командой `wiki-sync`, а страницы правятся в формате хранения
Confluence командой `wiki-edit`. Читайте вики по копии, меняйте — через `wiki-edit`.

## Настройки и пути

Настройки лежат в `.env` в корне проекта. **Сам `.env` не читайте и не выводите**: в нём пароли.
Пути по умолчанию:

| Что | Где |
|---|---|
| Копия вики | `wiki/` (настройка `WIKI_DIR`) |
| Страницы в работе | `_wiki-edit/` (настройка `WIKI_EDIT_DIR`) |

Если путь копии неочевиден, найдите папку с markdown-файлами, во front matter которых есть `wiki_page_id`.

## Сеть: кто запускает команды

Вики обычно доступна только из сети заказчика (VPN). Команды, которые ходят в вики, — `wiki-sync pull`,
`check`, `accept`, `clean` и `wiki-edit fetch`, `new`, `push` — **попросите выполнить пользователя** в его
терминале. Вы можете запустить их сами, только если пользователь прямо попросил и доступ есть.
`wiki-edit diff`, `check`, `status` работают без сети — их запускайте сами.

**`wiki-edit push` никогда не запускайте сами**, даже по просьбе: запись в вики делает человек после
подтверждения в терминале.

## Как читать копию

- Документ — одна страница вики. Страница с дочерними — папка с `README.md`, без дочерних — `<slug>.md`.
  Вложенность папок повторяет дерево страниц. Картинки — в `_assets/<slug>/` рядом.
- Front matter: `title` — точное название страницы, `wiki_page_id`, `wiki_version` — версия, с которой
  сверен документ, `wiki_parent_id`, `wiki_url`.
- Таблица с объёмными ячейками записана как набор записей: заголовок записи (`Шаг 3`, `Строка 2`,
  название из первой колонки) и под ним поля `- **Колонка:** значение`. Короткие таблицы — обычные
  markdown-таблицы.
- Ссылка на страницу, которая есть в копии, — относительная ссылка на документ. Ссылка на адрес вики
  означает, что страницы в копии нет (вне области синхронизации или нет доступа): не додумывайте её
  содержимое — попросите пользователя прислать текст или расширить область (`WIKI_ROOTS`/`WIKI_SPACE`).
- Ищите `grep -rn` по папке копии: по названию, тексту, идентификатору.
- Метки `<<<<<<<` в документе — неразрешённый конфликт после `pull`: правки из вики и локальные правки
  пересеклись. Скажите об этом пользователю.

## Обновление копии

Пользователь выполняет `wiki-sync pull`. Первый запуск выгружает всю область, следующие переносят только
изменения: правки из вики накладываются на документы слиянием, локальные правки сохраняются. Удаление
документов исчезнувших страниц и картинок без ссылок `pull` предлагает сам и выполняет только после
ответа «да» в терминале. `wiki-sync check` показывает, что изменилось, ничего не трогая.

Документы копии — зеркало вики: **не правьте их ради изменения требований**, правка не попадёт в вики.

## Правка страницы вики

1. По копии найдите страницу и место правки. Назовите пользователю страницу (название и `wiki_page_id`).
2. Попросите пользователя взять её в работу: `wiki-edit fetch <путь к документу .md или wiki_page_id>`.
   Появятся `_wiki-edit/<id>.xml` (его правите), `<id>.orig.xml` и `<id>.json` (не трогайте).
   Новая страница: `wiki-edit new --parent <id родителя> --title "…"`, по образцу существующей —
   с `--template <id образца>`. Ключ рабочих файлов новой страницы — `new-<название>`.
3. Внесите правку в `_wiki-edit/<id>.xml` по правилам ниже.
4. Запустите `wiki-edit diff <id>` и `wiki-edit check <id>`. Исправьте ошибки, покажите пользователю
   читаемую разницу и предупреждения.
5. Пользователь выполняет `wiki-edit push <id>`, затем `wiki-sync pull`. Если страницу успели изменить
   в вики после `fetch`, `push` откажет: нужно `wiki-edit fetch <id> --force` и повторить правку.

### Правила правки XML

Файл — формат хранения Confluence: обычные теги (`p`, `table`, `ul`, `h1`…) и макросы (`ac:…`, `ri:…`).

- Правка точечная. Не переформатируйте файл, не меняйте отступы и переносы строк, не трогайте разметку
  вне места правки: любое лишнее изменение попадёт в историю страницы.
- Новую строку таблицы, пункт или раздел делайте копией соседнего и меняйте содержимое — так сохраняется
  оформление (классы, атрибуты, порядок колонок).
- Макросы (`ac:structured-macro`) не удаляйте и не меняйте их параметры без прямой просьбы. У копии
  макроса удалите атрибут `ac:macro-id` — вики выдаст новый.
- Ссылку на страницу вики оформляйте по образцу уже имеющихся в файле (`ac:link` + `ri:page`).
- Картинку добавить в файл нельзя: вложение должно быть загружено на страницу. Скажите пользователю,
  какую картинку и куда загрузить в вики вручную.
- В тексте экранируйте `&`, `<`, `>` (`&amp;`, `&lt;`, `&gt;`).
- Если на странице ведётся лист изменений — добавьте строку по образцу существующих.
- Снятое требование не удаляйте молча: зачеркните (`<s>…</s>`) или удалите с записью в листе изменений,
  как принято на странице.
- Имена методов, параметров и значения пишите так, как они выглядят в источнике, без перевода.
- Не выдумывайте факты. Чего нет в исходных материалах — не пишите на страницу, а перечислите вопросы
  в ответе.

## Ошибки

| Сообщение | Что делать |
|---|---|
| «не задан адрес вики», «не задан доступ к вики», «не задана область синхронизации» | Пользователь дописывает `.env` по `.env.example` пакета |
| «вики ответила 401», «вход … не удался» | Неверный доступ, капча или SSO — пользователю войти в браузере или задать `WIKI_COOKIE` |
| «вики недоступна» | Нет сети до вики — включить VPN |
| `command not found: wiki-sync` | Пакет не установлен: `pipx install git+<адрес репозитория atlassian-tools>` |
